# AI 论文收集助手设计

日期：2026-10-30。状态：需求已整理，等待书面设计审阅；尚未开发、配置定时任务或执行删除。

## 目标与已确认范围

面向个人使用，收集 AI 领域最新和热门论文。由用户决定何时收集，不自动按日或按周检索、下载新论文。结果保存到本地；PDF 转 Markdown 完全在本机执行，不调用在线 PDF 解析服务。

收集后生成本次中文简报。每周总结已经收集的文档，形成独立总结文档，并使用固定论文编号定位依据。清理由用户选择对象、范围和删除方式后确认执行，不自动删除。

## 方案比较与建议

1. 推荐：Python 本地命令入口、明确的工作流、单个模型负责筛选与总结、SQLite 索引、文件保存正文。容易测试，符合现有样例基础。
2. 本地网页界面：便于勾选论文与删除范围，但增加界面工作，作为后续扩展。
3. 多 Agent 分工：增加调用成本与调试复杂度，第一版不采用。

这些是拟议实现方案，尚未选定具体转换库、模型服务和界面。

## 收集工作流

用户指定时间范围、主题（可选）和数量上限，查询论文元数据，按来源标识去重，筛选后下载 PDF，执行本机转换，检查转换状态与 Markdown 格式，再生成本次简报。

最新与热门分别展示。热度必须附可核验来源、信号及采集时间；缺少信号时标记未知，不用模型凭印象编造排名。arXiv 作为首个拟接入论文源，热门信号来源需在实现前核验可用性。

默认数量建议为每次最多 10 篇；具体采纳情况由后续设计审阅决定。下载重试、页数和文件大小应有上限，避免失控下载与模型调用。

## 转换与校验

PDF 转换器在本机运行，需先用机器硬件与代表性双栏、公式、表格论文验证效果，再锁定依赖。转换模型如需首次下载，下载完成后的解析不向在线服务上传论文。

复用原始样例的 PyMarkdownApi().scan_path() 及结果格式化逻辑，将论文 Markdown、本次简报、每周总结纳入检查。对学术公式、HTML 表格等特殊内容显式配置规则，不自动改写公式和研究内容来消除告警。

格式检查和内容完整性分别记录。检测空输出、页面处理失败和明显内容缺失；无法证明所有公式、图片和阅读顺序完全正确，异常材料标记待复核。失败不能报告为成功，也不能声称完整阅读全文。

## 文件与编号

论文分配固定编号 P000001，编号永久不复用。来源 ID 与本地编号独立记录；同一论文版本用 v1、v2 区分。

```text
library/
  index.md
  collection.sqlite
  papers/P000001/v1/
    original.pdf
    paper.md
    assets/
    metadata.json
    validation.json
  briefs/日期-收集批次.md
  weekly/年-W周号.md
  temp/
```

索引记录标题、作者、来源 ID、版本、收集时间、各类文件位置和存在状态。周报引用使用 [P000001/v1]，不要求链接。删除文件后编号仍能查到论文身份与文件状态；缺失正文不显示为可本地阅读。

## 每周总结

按北京时间的自然周组织本周收集记录，归纳主要方向、方法差异、作者报告的结果、局限和建议阅读顺序。事实与跨论文比较必须关联论文编号及版本，模型推断需明确标记。

不只是拼接本次简报；使用可用全文，只有摘要时明确标注。文件缺失或转换失败时，在覆盖情况中说明。没有新增材料时记录无新增，不生成虚构趋势。

每周自动总结的具体时间尚未确定，部署时需明确本机开机、任务补跑与重复执行策略。现阶段不创建任何定时任务。

## 四种清理方式

| 选项 | 删除范围 |
| --- | --- |
| 只删 PDF | 所选论文版本的原始 PDF |
| 只删 Markdown | 所选论文版本的 Markdown 正文，及确认不再被其他文件引用的附件；保留简报周报 |
| 只删总结 | 用户明确选中的简报或周报；保留论文全文 |
| 全部删除 | 用户所选范围内、预览明确列出的 PDF、Markdown、专属附件和总结 |

先选择论文、版本或日期范围，再选择方式。预览列出每个文件、关联论文、受影响总结和预计释放空间，确认后执行。多论文共享周报不会因选中其中一篇而自动删除，必须在清理预览中明确选中该周报。

全部删除仍保留最小编号索引与删除记录，避免编号复用和历史引用失去身份。此约定沿用已确认的索引保留规则。

程序限定删除根目录，校验规范化真实路径及链接目标，不允许逃逸到资料库以外。确认后若目标清单变化，重新预览；重复执行不报虚假成功。部分失败逐项记录真实删除状态，索引与现有文件保持一致。

## 代码、权限与状态

产品应位于独立目录及 Git 仓库，原 markdown_validator 保持参考样例身份。原设计保留九个职责目录；2026-11-02 按用户要求调整为只保留实际使用的目录，移除无独立实现的 memory/、context/、skills/ 占位说明。

工作流控制顺序、重试和停止；Agent 只负责筛选与总结；工具分别实现查询、下载、转换、格式检查、保存与删除。模型不能绕过删除确认或执行任意系统命令。

SQLite 保存收集批次、步骤状态、论文、版本、报告引用和删除记录，支持中断后按状态继续。编号分配和重复运行由程序保证。第一版不引入向量数据库，不自动写入长期用户记忆。

记录运行 ID、来源、版本、工具状态、耗时、模型调用量和可获得的费用。密钥及完整私有正文不进入日志。检索内容和论文文本作为数据，不能覆盖程序权限。

## 验收

- 同一来源论文重复收集不重复下载；不同版本可追踪。
- 本机完成 PDF 转 Markdown；无在线解析请求。
- 三类 Markdown 均真实执行格式检查，异常与全文缺失如实记录。
- 简报与周报的每个论文编号均能查到身份和对应版本状态。
- 四种清理只删除预览并确认的目标；覆盖越界、共享周报、缺失文件、部分失败等测试。
- 固定论文样本验证筛选依据、总结事实、来源编号、转换失败出口和热门信号缺失情况。
- 未运行测试、模型评估或真实下载不得标为通过；费用和质量改善需有实测依据。

独立产品目录、本机配置、模型运行位置和费用边界、用户操作入口、每周总结执行时间。已确认的本机 PDF 解析要求不自动等同于摘要模型也必须本地运行。先核验硬件，再提供本地模型与在线模型的具体取舍。
